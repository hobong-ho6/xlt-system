## 🎯 테스트 방법론

### 핵심 원칙
1. **개발자 우선 테스트**: 사용자 테스트 전 개발자가 먼저 검증
2. **완전 삭제 → 재설치**: 신규 사용자 관점 테스트
3. **근본적 해결**: 임시 해결책 금지, 설치 스크립트 자체 개선
4. **3가지 시나리오**: 정상, 비정상, 경계값 테스트
5. **웹 UI 필수 테스트**: 버튼, 폼, 모달 등은 반드시 브라우저에서 실제 테스트 후 보고

### 테스트 플로우
```
기능 개발 완료
    ↓
개발자 자체 테스트 (완전 삭제 → 재설치)
    ↓
통과? → YES → 사용자 테스트 (다른 PC)
    ↓              ↓
   NO             통과?
    ↓              ↓
근본적 수정       배포 완료
    ↓
재테스트
```

### 🌐 웹 UI 테스트 프로토콜 (CRITICAL)

**웹 UI 기능 (버튼, 폼, 모달 등) 개발 시 필수 테스트:**

```bash
# 1. 로컬 서버 시작
cd ~/XLT-System
python3 stable_web_server.py

# 2. 브라우저에서 해당 페이지 접속
open http://localhost:5004/[해당페이지]

# 3. 실제 사용자 시나리오대로 상호작용
# - 입력 필드에 값 입력
# - 버튼 클릭
# - 모달 열기/닫기
# - 드롭다운 선택
# - 토글 스위치 조작 등

# 4. 브라우저 개발자 도구 확인 (F12)
# - Console 탭: JavaScript 에러 없는지 확인
# - Network 탭: API 요청/응답 200 OK 확인
# - 성공/실패 메시지 정상 표시 확인

# 5. 모든 단계 정상 작동 확인 후에만 "배포 완료" 보고
```

**❌ 금지 사항**:
- 코드만 보고 "작동할 것이다" 추측하여 보고
- curl로만 API 엔드포인트 테스트하고 UI 생략
- 사용자에게 테스트 부담 전가 ("테스트해주세요")

**실제 실패 사례 (v3.3 교훈)**:
